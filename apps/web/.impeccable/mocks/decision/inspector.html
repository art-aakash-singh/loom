Postgres: index scan vs seq scan

4 turns · 2,915 tokens
Why does Postgres ignore my index on messages.conversation_id and do a seq scan instead? The table has about 40k rows.

Postgres estimates the cost of each plan from table statistics. When a predicate matches a large fraction of rows, a sequential scan wins: reading pages in order is cheaper than jumping between the index and the heap.

Check what the planner believed with:

EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM messages WHERE conversation_id = $1;

If rows= in the estimate is far from the actual count, run ANALYZE messages or raise the statistics target on that column.
